# 002 — One content model, explainable readiness, and reviewed artifacts

Accepted 2026-09-17.

Keep readiness in domain functions over declarative fields. Required stages and applicability are explicit; unknown values do not resolve requirements. Voting requirements remain active until a church explicitly records an alternative decision process. Neither free-text authority nor a preset silently waives them.

Render shared document sections to Markdown and standalone printable HTML, then package both with fflate. Use browser printing for PDF. Include a dated, private project backup in the full ZIP. Store approval only after an explicit user record and invalidate it after content changes. Readiness is not church approval.

Keep presets separate as suggestions until each value is copied through an explicit review action. A separately typed, allowlisted church template excludes active-search fields. This is an architectural boundary, not a claim that arbitrary free text is automatically sanitized. Public sharing and cycle archival are deferred.

A bundled, labeled sample is temporary until duplicated as a local project. Sample rules are never new-project defaults. Qualification labels use plain wording and references rather than translation-specific branding, following the owner’s editorial instruction.
