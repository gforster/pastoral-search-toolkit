# Content model

The source audit predates the initial implementation. The continuation expands that model without changing the source church’s rules into universal defaults.

`src/content/core/workbook.js` defines modules, field applicability, explainable milestone rules, and the 26 qualification prompts. `questions.js` contains the adapted R00 bank. `src/content/guidance/` contains reusable pastoral principles and review prompts. `src/content/presets/` contains explicitly suggested, individually adoptable values. `src/artifacts/templates/` constructs sections from this content and allowlisted project answers; `renderers/` exports those same sections.

Content has distinct authority: Scripture framework; adopted doctrine or governing documents confirmed by the church; configured process; toolkit recommendation; optional practice. Toolkit readiness checkpoints indicate what the workbook needs for a meaningful milestone review. They do not assert that every field is a universal biblical or constitutional command.

The Fellowship example preserves source-derived composition and call rules only as labeled example configuration. Named people, private intentions, employer, exact transition dates and tenure are excluded. Quorum and notice remain unknown where the sources did not establish them. Music, theological, translation-practice, and cooperation positions remain topics for local review, not adopted defaults.

Qualification titles use contemporary descriptive labels with the original Scripture references and stable IDs. They are discussion headings, not a new Bible translation. Each church records meaning, evidence, contrary patterns, and interpretive questions. All four prompts precede adoption. Pastoral/theological reviewers should check these descriptions before treating a public preview as settled guidance.

Question banks are menus, not one mandatory interview. Selected core questions, adopted-conviction questions, custom follow-ups, and scenario prompts feed the interview guide. Candidate-specific answers and reference notes belong in securely stored exported forms, not a candidate database in the app.

No preset or artifact may invent quorum, vote thresholds, dates, pay, or doctrinal positions. Unknowns remain visible. Public handouts use explicit field allowlists; the complete package includes internal worksheets and a private backup and must be reviewed before sharing.
