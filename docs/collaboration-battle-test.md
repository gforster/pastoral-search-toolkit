# First committee battle test

Use a fictional candidate and a public or church-authorized sermon for the first practice run. The goal is to learn whether the process helps a small committee think independently and work together, without requiring technical skill. No analytics are collected. Keep feedback free of private candidate details.

## Practice workflow

1. Chair opens the shared search project and chooses **Committee work & candidates**. Add the local directory, using voting labels only as descriptive records.
2. Add a fictional candidate and an evidence title/link. Create a sermon review round, select expected reviewers and choose the evidence/context deliberately.
3. Download a **Review Packet** for each selected recipient and deliver it through the church's existing private channel. Do not send the full project backup for this task.
4. Each reviewer opens **Individual reviews**, imports the packet, confirms their display name and records observations independently. No other reviews are in the packet. Try part of the work offline after loading the app.
5. The reviewer downloads **Completed Review** and returns the JSON file. A paper user can print the worksheet; the chair may transcribe it through the same assigned packet, noting the transcriber in overall observations and checking the wording with its author.
6. Chair imports several completed files at once. Confirm that six of seven shows six of seven, and that an unassigned submission does not count as an expected member's response.
7. Try an exact duplicate, a revised submission, a different candidate's review and an older criteria snapshot. Review the explanations; verify that nothing silently replaces another person's work.
8. Close submissions and release the compilation at the appropriate time. Discuss divergent observations and every material concern. Counts are observations, not a candidate score or vote.
9. Record the committee's actual conclusion and rationale, unresolved concerns, any actual result and recorder. Add follow-up with an owner/date; it becomes an ordinary assignment. Verify that this does not silently approve workbook prerequisites.
10. Download a private full-project backup and restore it in a separate browser profile. Inspect the candidate, round snapshot, individual submissions, previous revisions and decision history. Test a reusable template separately and verify that it contains no candidate/review records.

## Questions to ask afterward

- Was review-packet creation understandable? Did selecting one recipient at export feel helpful or tedious for a 5–10-person committee?
- Could members find **Individual reviews**, import the packet and understand the categories?
- Did local save feedback and completed export make it clear that the chair had not received anything automatically?
- Could the chair import several files? Were duplicate, mismatch, stale-criteria and closed-round explanations understandable?
- Did the compilation improve discussion? Did independent work appear to reduce anchoring? What other influences remained?
- Did a quiet member's concern remain visible when others reported none? Was missing evidence distinguished from a negative judgment?
- Was exact-wording question grouping enough, or did manual grouping of differently worded questions take substantial effort?
- Did people confuse local reviewer names with verified identity, completion with attendance, or process status with candidate quality?
- Were assignments and decision records useful? Did recording a follow-up as a task save work or duplicate something already maintained elsewhere?
- Was separate handling of shared facts, personal observations and committee conclusions visually clear?
- Did the paper/transcription option work for members with different technology comfort levels?
- What still required email, paper, spreadsheets or external secure storage? Which of those tools should remain external?
- Did the committee need discussion threads, or were meetings plus structured records sufficient?
- Did previewing reusable template wording prevent private or transition-specific text from being carried forward?
- What felt unnecessarily complicated? Which future server features would remove an observed problem?

Record date, role (not private candidate name), device/browser, task attempted, expected behavior, actual behavior, workaround and priority. Submit sanitized product feedback in the repository; never attach real committee backups to public issues.

## Known limits to evaluate

Local identities are self-entered. Directory roles do not restrict access to this browser. Release is a local workflow guard, not encryption. Exported files cannot be revoked. Copies of a full project are not synchronized; the chair remains the record keeper. Review snapshots are immutable; changed instructions/criteria require a new round. Revision replacement is explicit and retains up to ten prior submissions. Full project backups are limited to 10 MB and individual portable review files to 750 KB. No evidence attachments are downloaded or stored by the toolkit. Search-wide archival and granular retention tools are deferred; keep sensitive source files in the church's authorized records system.
